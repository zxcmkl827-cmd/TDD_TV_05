## 핵심 발견

**SRP:** `TVController`가 숫자 입력 FSM, 채널 검증/적용, 선호 채널 CRUD, 다음 선호 채널 탐색을 한 클래스에서 처리합니다. 변경 이유가 4가지 이상이라 SRP가 약합니다.

**OCP:** `PressNumber` / `PressFavorite` 등 고정 public API 구조라, README의 채널 업·다운·검색 등을 넣으면 클래스 수정·분기 증가가 불가피합니다. `remoteKey`는 있으나 현재 구현에서 미사용입니다.

**매직 넘버:** 본문에는 `-1`, `0`, `99`, `10`이 있습니다. 질의하신 `50`, `11`, `6`은 `TVController`에 없고(각각 Mock/테스트 데이터), 보고서에 구분해 두었습니다.

**치명 이슈 (우선순위 1):**
- L18 잔존 문자 `햣` → 컴파일 실패 가능
- `PressNextFavorite()`에서 `*FavoriteChannels.end()` → UB (의도는 `front()` 순환으로 보임)

## 분석 표 (요약)

| 문제점 | 위반 원칙/스멜 | 영향 | 개선 방향 | 우선순위 |
|--------|----------------|------|-----------|----------|
| `PressNumber()` 내 `햣` | 빌드 결함 | 컴파일 실패 | 즉시 제거 | **1** |
| `PressNextFavorite()` `end()` 역참조 | 버그/UB | 크래시·순환 실패 | `FavoriteChannels.front()` | **1** |
| 입력+채널+선호 채널 단일 클래스 | SRP | 회귀 범위 확대 | `FavoriteStore` / `ChannelInputBuffer` 분리 | **2** |
| push + sort / stoi 중복 | Duplicated Code | 정책 변경 시 N곳 수정 | 헬퍼·값 객체 | **2~3** |

| `0`, `99`, `10` | Magic Number | 범위·자릿수 정책 분산 | `constexpr` 공통 상수 | **3~4** |
| 리모컨 기능 확장 | OCP | God class·switch 비대화 | `remoteKey` → handler 테이블 / `variant` FSM | **4** |
| `protected` 멤버, `<iostream>` | 캡슐화·의존 | 결합도 | `private`, include 정리 | **5** |

## C++17 개선 방향 (요약)

- **단기:** `std::optional<int>` 또는 `enum class`로 `-1` 센티널 제거, `constexpr` 채널 상수.
- **중기:** `FavoriteChannelStore` 분리(SRP), `GetCurrentChannelInt()`로 `stoi` 일원화.
- **확장 시:** `unordered_map<remoteKey, Handler>` 테이블 디스패치(OCP), 검색·다중 상태는 `std::variant` FSM.

## 리팩토링 우선순위

1. 빌드 오류·UB 수정 (정확성)  
2. 선호 채널 로직 캡슐화 + 중복 제거 (SRP/DRY)  
3. 매직 넘버/`optional` (가독성, 무해 리팩토링)  
4. 채널 파싱·digit 검증·키 디스패치 스켈레톤 (확장 대비)  
5. 접근 제어·include·자료구조 최적화 (유지보수)
