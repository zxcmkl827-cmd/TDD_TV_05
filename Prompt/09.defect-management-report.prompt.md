### 문서 구성

1. **결함 분류 체계**
   - Severity 정의(Critical/Major/Minor/Info) 및 릴리스·SLA
   - **Severity × 영향 매트릭스** (프로덕션/인프라/문서 × 기술 심각도)
   - 실제 사례 매핑: DEF-TV-001~003, DEF-BLD-001
   - ItemType, 상태 전이(New → … → Closed)

2. **결함 보고서 템플릿**
   - 필드: 재현·기대·실제·원인·수정·검증
   - `defect_list.md`에 붙여 넣을 **복사용 Markdown 블록**
   - 요구사항(C-*, E-*)·`test_plan` TEST_F 추적 표

3. **품질 메트릭 수집 계획**
   - 테스트 통과율, line/branch/함수 커버리지, 단계별 발견율, 결함 밀도, Critical 잔존
   - PowerShell `ctest` 명령·기록 형식(Not Run 포함)
   - 단위→통합→시스템→빌드→요구검토 단계별 발견율 정의
   - **gcov/lcov** 절차, PR 게이트(90% line), `CMakeLists.txt` 커버리지 현황 반영

4. **(선택) GitHub Issues**
   - Label·ID 매핑, mermaid 워크플로, PR 체크리스트, `gh issue create` 예시

개별 결함 상세는 기존처럼 **`docs/defect_list.md`**가 원장이고, 본 문서는 **프로세스·분류·메트릭** 가이드입니다. 원장과 교차 링크해 두었습니다.
