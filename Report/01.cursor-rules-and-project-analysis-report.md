# TV Controller C++ 프로젝트 작업 보고서

작성일: 2026-05-19

## 1. 작업 개요

본 보고서는 Gilded Rose C++17 기반 TV Controller 프로젝트에서 지금까지 수행한 Cursor AI 규칙 작성 및 코드 구조 분석 결과를 정리한 문서입니다.

수행한 주요 작업은 다음과 같습니다.

- 프로젝트 루트에 `.cursorrules` 파일 생성
- C++ 프로젝트 전체 구조 분석
- 주요 클래스 역할과 책임 정리
- 클래스 간 의존성 관계 분석
- State 패턴 구현 방식 검토
- Test Double 사용 패턴 분석
- 분석 결과를 `docs/analysis.md`에 저장

## 2. Cursor AI 프로젝트 규칙 작성

프로젝트 루트에 `.cursorrules` 파일을 생성하여 Cursor AI가 해당 프로젝트에서 따라야 할 기본 규칙을 정의했습니다.

### 반영된 기술 스택

- C++17
- CMake
- Google Test
- gcov/lcov 기반 커버리지 확인

### 절대 규칙

다음 파일은 레거시 호환성 경계로 취급하도록 명시했습니다.

- `Tuner.h`
- `remoteKey.h`

해당 파일의 구조체, 필드, 이름, 공개 계약은 수정하지 않도록 규칙화했습니다.

### 테스트 규칙

테스트 작성 시 다음 규칙을 따르도록 정의했습니다.

- 모든 단위 테스트는 Google Test 사용
- 테스트 이름은 `should_[결과]_when_[조건]` 형식 사용
- 프로덕션 동작 변경 전 테스트를 먼저 추가 또는 수정
- 리팩토링 전 기존 레거시 동작을 테스트로 보호
- 커버리지에 민감한 변경은 gcov/lcov로 확인

### 리팩토링 규칙

리팩토링은 테스트가 Green 상태일 때만 진행하도록 했습니다.

또한 다음 원칙을 포함했습니다.

- 기존 동작 보존
- 작은 단위의 점진적 리팩토링
- 매직 넘버 상수화 권장
- 함수 하나는 가능한 한 20줄 이하 유지
- 주석보다 명확한 이름 우선

중첩된 `TDD_TV_05` 폴더도 존재하지만, 현재 루트 프로젝트의 메인 구현과는 분리된 초기 실습용 스냅샷에 가깝습니다.

## 4. 주요 클래스 역할과 책임

### Tuner

`Tuner`는 외부 튜너 업체가 제공하는 기능을 추상화한 인터페이스입니다.

주요 책임:

- 현재 채널 기준으로 다음 시청 가능 채널 검색
- 지정 채널로 현재 채널 변경
- 현재 채널 값 반환

`TVController`는 구체 구현이 아닌 `Tuner` 인터페이스에 의존합니다.

### DevTuner

`DevTuner`는 개발 및 테스트용 `Tuner` 구현체입니다.

주요 책임:

- 현재 채널 값을 메모리에 보관
- 유효 채널 범위 검증
- 채널 목록 기반 `seekCH()` 동작 제공

테스트 관점에서는 실제 튜너 장비를 대신하는 Fake 역할을 합니다.

### TVController

`TVController`는 리모컨 입력을 해석하고 채널 변경 및 선호 채널 관리를 수행하는 핵심 도메인 클래스입니다.

주요 책임:

- 숫자 입력 버퍼링
- 한 자리 또는 두 자리 채널 입력 처리
- 선호 채널 추가/삭제
- 다음 선호 채널 이동
- 최종 채널 변경을 `Tuner`에 위임

### remoteKey

`remoteKey`는 리모컨 키를 표현하는 enum입니다.

현재 루트의 메인 `TVController` 구현에서는 직접 사용되지 않지만, 레거시 인터페이스로 유지해야 하는 파일입니다.

## 5. 클래스 간 의존성 관계

핵심 의존성은 다음과 같습니다.

```text
TVController
  └── Tuner 인터페이스에 의존

DevTuner
  └── Tuner 인터페이스 구현

MockTuner / MockTunerForController
  └── Google Mock으로 Tuner 인터페이스 대체

TVControllerTest
  ├── TVController 사용
  └── DevTuner 사용

TVControllerMockTest
  ├── TVController 사용
  └── MockTunerForController 사용

ApprovalTest
  ├── TVController 사용
  └── DevTuner 사용
```

`TVController`가 생성자 주입으로 `Tuner&`를 받기 때문에 실제 구현체, Fake, Mock을 자유롭게 교체할 수 있습니다. 이 구조는 테스트 가능성을 높이는 중요한 설계 포인트입니다.

## 6. State 패턴 구현 방식

현재 프로젝트에는 GoF State 패턴처럼 별도의 `State` 추상 클래스와 구체 상태 클래스가 존재하지 않습니다.

대신 `TVController` 내부의 `ChannelBuffer` 값으로 입력 상태를 표현하는 암묵적 상태 머신 구조입니다.

```text
Idle 상태
  - ChannelBuffer == -1
  - 처리 중인 숫자 입력 없음

DigitBuffered 상태
  - ChannelBuffer != -1
  - 한 자리 숫자가 입력되어 다음 입력 또는 확인을 기다림
```

상태 전이는 다음과 같이 동작합니다.

- `PressNumber()`가 처음 호출되면 숫자를 버퍼에 저장합니다.
- 두 번째 숫자가 입력되면 두 자리 채널을 계산하고 튜너에 적용합니다.
- `PressConfirm()`이 호출되면 버퍼에 있는 한 자리 채널을 적용합니다.
- `PressOthers()`가 호출되면 입력 버퍼를 취소합니다.

현재 기능 범위에서는 단순 상태 머신으로 충분하지만, 채널 검색, 채널 업/다운, 검색 결과 기반 이동 기능이 확장되면 명시적 상태 enum 또는 State 객체 분리를 고려할 수 있습니다.

## 7. Test Double 사용 패턴

프로젝트는 Fake, Mock, Approval Test를 함께 사용합니다.

### Fake

`DevTuner`는 실제 튜너 대신 동작하는 Fake입니다.

사용 위치:

- `TVControllerTest.cpp`
- `ApprovalTest.cpp`

주요 목적:

- 실제 현재 채널 값이 바뀌었는지 검증
- 선호 채널 상태를 검증
- 외부 장비 의존성 제거

### Mock

`MockTuner`, `MockTunerForController`는 Google Mock 기반 Test Double입니다.

사용 위치:

- `TunerTest.cpp`
- `TVControllerMockTest.cpp`

주요 목적:

- `setCH()` 호출 여부 검증
- `getCurrentCH()` 반환값 제어
- 예외 상황 시뮬레이션
- `TVController`와 `Tuner` 사이의 협력 관계 검증

### Approval Test

`ApprovalTest.cpp`는 여러 입력 시나리오의 결과를 문자열로 만들고 승인 파일과 비교합니다.

이는 리팩토링 중 레거시 동작을 보호하는 Golden Master 테스트로 볼 수 있습니다.

## 8. 발견된 주요 이슈

분석 과정에서 다음 사항을 확인했습니다.

### 컴파일 오류 가능성

`src/TVController.cpp`의 `PressNumber()` 내부에 독립적인 한글 문자 `햣`이 남아 있습니다. 현재 상태로는 컴파일 오류를 유발할 가능성이 있습니다.

### 다음 선호 채널 순환 로직 결함 가능성

`PressNextFavorite()`에서 현재 채널보다 큰 선호 채널이 없을 때 `*FavoriteChannels.end()`를 사용합니다.

`end()`는 마지막 원소가 아니라 마지막 다음 위치이므로 역참조하면 정의되지 않은 동작입니다. 의도는 첫 번째 선호 채널로 순환하는 것으로 보이므로 `FavoriteChannels.front()` 사용이 적절합니다.

### 테스트 이름 규칙 불일치

기존 테스트 이름은 `PressNumber1Confirm`, `FavoriteChannelAdd`, `testSetChForValidChannel` 등입니다.

새로 정의한 `.cursorrules`의 `should_[결과]_when_[조건]` 규칙과는 일치하지 않습니다. 향후 테스트 추가 또는 리팩토링 시 점진적으로 이름을 정리하는 것이 좋습니다.

### README 요구사항 대비 미구현 기능

README에는 채널 검색, 채널 업/다운, 검색 결과 기반 이동 요구사항이 포함되어 있습니다.

현재 구현에서 명확히 확인되지 않은 기능은 다음과 같습니다.

- 채널 검색 버튼 처리
- 채널 업
- 채널 다운
- 검색된 채널 목록 기반 이동

## 9. 향후 개선 제안

우선순위가 높은 개선 방향은 다음과 같습니다.

1. `src/TVController.cpp`의 컴파일 오류 가능 문자 제거
2. `PressNextFavorite()` 순환 로직을 테스트로 보호한 뒤 수정
3. `ChannelBuffer == -1` 매직 넘버를 이름 있는 상수 또는 명시적 상태 enum으로 변경
4. 신규 테스트부터 `should_[결과]_when_[조건]` 네이밍 규칙 적용
5. README의 미구현 기능을 테스트로 먼저 정의한 뒤 구현
6. 리팩토링 전후 Google Test와 Approval Test를 모두 실행
7. 커버리지 변경이 중요한 경우 gcov/lcov 결과 확인

## 10. 결론

현재 프로젝트는 `TVController`가 도메인 로직을 담당하고, `Tuner` 인터페이스를 통해 외부 튜너 의존성을 분리한 테스트 가능한 구조를 갖고 있습니다.

State 패턴은 명시적 클래스 기반이 아니라 `ChannelBuffer`를 이용한 암묵적 상태 머신 방식으로 구현되어 있습니다.

Test Double은 목적에 따라 구분되어 사용되고 있습니다.

- `DevTuner`: 상태 기반 검증용 Fake
- `MockTuner`, `MockTunerForController`: 협력 호출 검증용 Mock
- `ApprovalTest`: 레거시 동작 보호용 Golden Master 테스트

향후 리팩토링은 `.cursorrules`에 정의한 대로 테스트 Green 상태를 유지하면서 작고 점진적으로 진행하는 것이 적절합니다.
