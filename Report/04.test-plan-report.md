## 2. 테스트 전략 요약

### 2.1 목적

`TVController`의 리모컨 입력 처리(숫자 버퍼, 채널 적용, 선호 채널)를 **재현 가능한 TEST_F 단위 테스트**로 고정하고, README 미구현 기능(채널 검색·업/다운)은 **선행 Red 테스트**로 요구사항을 잠근 뒤 구현한다.

### 2.2 테스트 더블 역할

```text
TVController
    ├── DevTuner (Fake)     → ControllerTest : 최종 채널 상태 검증
    ├── MockTuner (Mock)    → TVControllerMockTest : setCH/getCurrentCH 호출 계약
    ├── MockTuner (Mock)    → TunerTest : Tuner 인터페이스·파라미터화 경계
    └── ApprovalTest        → 복합 시나리오 Golden Master (보조)
```

**원칙:** 동일 시나리오를 Fake(상태)와 Mock(협력) 쌍으로 유지해 거짓 Green을 방지한다.

### 2.3 In / Out of Scope

| In Scope | Out of Scope |
|---|---|
| `PressNumber`, `PressConfirm`, `PressOthers`, 선호 채널 API | 외부 Tuner 실장비 검증 |
| `ApplyChannel` / `IsValidChannel` 경계 | `remoteKey` 매핑 계층 |
| 미구현 검색·업/다운의 TDD Red 테스트 | UI·네트워크·동시성 |

## 5. 경계값 케이스 목록

### 5.1 채널 번호 (`ApplyChannel` / `IsValidChannel`)

| 구분 | 값 | 기대 |
|---|---|---|
| 하한 유효 | `0` | `setCH("0")` |

| 상태 | 조건 | 기대 |

### 7.3 측정 절차 (Linux / WSL / MSYS2)

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug -DCMAKE_CXX_FLAGS="--coverage"
cmake --build build
ctest --test-dir build --output-on-failure

lcov --capture --directory build --output-file build/coverage.info
lcov --remove build/coverage.info \
  '*/test/*' '*/googletest/*' '*/gmock/*' '*/ApprovalTests/*' \
  --output-file build/coverage.filtered.info
genhtml build/coverage.filtered.info --output-directory build/coverage_html
lcov --summary build/coverage.filtered.info
```

MSVC 네이티브는 gcov 미지원 → WSL/Linux CI 또는 OpenCppCoverage 사용.

## 11. 결론

`TVController`는 **Fake·Mock·Approval**로 구분된 테스트 가능 구조를 갖추었으나, **계획 30건 중 9건만 TEST_F로 구현**되어 있으며 README의 검색·업/다운 및 숫자 입력 고급 시나리오가 대부분 미검증 상태입니다.

**핵심 결론**

1. **P0 선행** — `Report/03`의 컴파일 결함·`PressNextFavorite` UB를 Red 테스트로 고정한 뒤 수정  
2. **이중 검증** — 동일 시나리오를 `ControllerTest`(상태)와 `TVControllerMockTest`(호출)에 쌍으로 추가  
3. **TDD 확장** — C-15~C-22는 API 구현 전 Red 테스트 작성  
4. **커버리지** — `TVController` line **90% 이상**, lcov 필터·`genhtml`로 갭 분석  
5. **추적성** — `docs/test_plan.md`의 C-/M-/E-/S- ID로 진행률 관리  

향후 테스트·구현 작업 시 **P0 → P1 → 미구현 TDD → 커버리지 게이트** 순으로 진행하고, 각 단계마다 `TVControllerTest` / `TVControllerMockTest` / `ApprovalTest`를 Green으로 유지하는 것을 권장합니다.
